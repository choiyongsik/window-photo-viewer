# 골라보기 (window-photo-viewer)

촬영 직후 JPEG/PNG 폴더를 키보드로 훑으며 별점을 매기는 Windows 뷰어 — 사진을 **골라** 별점 매기며 **보기**. 창 제목·설치 프로그램·시작 메뉴에는 「골라보기」로 표시되고, 실행 파일·설정·캐시 경로는 `WindowPhotoViewer`를 그대로 쓴다.
지원 포맷: `.jpg` `.jpeg` `.png` 이미지, `.mp4` `.mov` 영상.
별점·색 라벨은 **이미지 내장 XMP**(`xmp:Rating`, `xmp:Label`)에 기록되어 Lightroom Classic 임포트 시 그대로 읽힌다.

## 실행

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
python app.py D:\Photos\2026-08-27
```

인자를 생략하면 마지막으로 열었던 폴더를 다시 연다.

## 폴더 패널

창 왼쪽에 **루트 폴더 기준 트리**가 표시된다. 루트는 처음 여는 폴더(또는 마지막으로 사용한 루트)로 정해지고, 그 아래 하위 폴더들이 펼칠 때마다 지연 로딩되며(펼치기 전까지는 하위 폴더를 읽지 않는다) 각 항목에 이미지·영상 개수가 백그라운드로 채워진다 (`23장 · 1영상`). 항목을 클릭하면 그 폴더를 연다. `PgUp`/`PgDn`은 트리에서 현재 펼쳐진 순서(형제·자식 포함)로 이전/다음 폴더로 이동한다.

`Ctrl+O`로 루트 안의 폴더를 열면 루트는 그대로 유지된다. 루트 밖의 폴더를 열면 그 폴더가 새 루트가 된다. `Alt+↑`(메뉴 파일 → "루트 한 단계 위로")는 루트를 한 단계 위 폴더로 바꿔 트리를 위로 확장한다 — 현재 보고 있는 폴더는 그대로 유지된다. 메뉴 파일 → "현재 폴더를 루트로"는 지금 열려 있는 폴더를 새 루트로 지정한다.

한 번 펼쳐서 읽어들인 폴더는 디스크에서 하위 폴더가 새로 생기거나 지워져도 트리에 자동 반영되지 않는다 — 루트를 다시 지정(`Alt+↑`, "현재 폴더를 루트로")하거나 프로그램을 재시작해야 최신 상태로 다시 읽는다.

패널 폭은 경계를 드래그해 조절할 수 있고, 이 폭은 다음 실행에도 유지된다. `Ctrl+B`로 패널을 숨기거나 다시 보일 수 있고, 이 설정도 다음 실행에 유지된다.

### ★ 별점 있는 사진 모아보기

트리 맨 위의 **"★ 별점 있는 사진"** 항목(또는 `Ctrl+Shift+R`, 메뉴 보기 → "★ 별점 있는 사진 모아보기")을 클릭하면 **루트 아래 모든 폴더**를 훑어 별점 1 이상인 사진·영상을 한 목록으로 보여준다. Reject(✕)는 포함하지 않는다 — Reject는 폴더를 연 뒤 `Alt+X`로 본다.

- 수집은 백그라운드에서 진행되고 상태 표시줄에 `N폴더 · M장 확인 · ★K`로 진행 상황이 보인다. 끝나면 목록이 한 번에 바뀌고 항목 텍스트에 `(K장)`이 붙는다. 수집 중 다른 폴더를 클릭하면 즉시 취소된다.
- 목록의 항목은 여러 폴더에서 온 것이므로 헤더에 `상위폴더/파일명`으로 표시된다. 별점·라벨 변경은 평소처럼 그 파일에 바로 기록된다.
- 이 화면에서는 폴더 자동 감시가 없다. 별점을 0으로 되돌린 항목도 `F5`(재수집) 전까지 목록에 남는다. `F5`는 현재 항목을 유지한 채 다시 수집한다.
- `Alt+↑`로 루트를 위로 넓히면 새 루트 기준으로 자동 재수집된다. 루트를 드라이브 최상위처럼 아주 넓게 잡으면 그만큼 오래 걸린다 — 진행 표시를 보며 기다리거나 다른 폴더를 클릭해 취소한다.
- 비용: 파일마다 JPEG 헤더의 XMP만 읽는다(파일 전체를 읽지 않음). SSD에서 수천 장은 수 초, 별점이 있는 파일만 EXIF를 추가로 읽는다.
- **별점 캐시**: 한 번 읽은 파일의 별점은 `%LOCALAPPDATA%\WindowPhotoViewer\ratings.json`에 `(경로, 수정시각, 크기)` 키로 기억된다(별점 없는 파일 포함). 다음 수집·폴더 열기 때는 수정시각·크기가 같은 파일을 열지 않고 stat만 비교하므로 HDD에서도 두 번째부터는 수 초다. Lightroom·이 뷰어·exiftool(기본)의 쓰기는 수정시각을 바꾸므로 자동으로 다시 읽힌다. **수정시각을 보존하며 XMP만 바꾸는 도구(`exiftool -P` 등)를 썼다면 `F5`** — F5는 캐시를 무시하고 전부 다시 읽어 캐시를 고친다(폴더 자동 감시로 인한 새로고침은 캐시를 그대로 쓴다). 캐시 파일은 지워도 된다.

## Lightroom Classic 호환 주의

- 임포트 **전**에 별점을 매기면 LR이 자동으로 읽는다.
- 이미 카탈로그에 있는 파일을 바꿨다면 LR에서 `Metadata → Read Metadata from File` 을 실행해야 반영된다.
- LR은 Pick/Reject 플래그를 파일로 주고받지 않는다. 이 뷰어의 Reject(`xmp:Rating=-1`)는 LR에서 "별점 없음"으로 보인다. Reject 모아보기(`Alt+X`)로 확인 후 삭제는 직접 한다.
- 영상(`.mp4` `.mov`)의 별점은 옆에 생기는 `영상명.xmp` 사이드카에 저장된다. LR은 이를 읽지 않는다 (뷰어 내부용, Bridge/digiKam 호환).

## 파일에 미치는 영향

- JPEG/PNG: XMP 패킷(PNG는 iTXt 청크)만 교체한다. 픽셀 데이터와 EXIF는 그대로. 임시 파일에 쓴 뒤 원자적으로 교체하므로 중간에 꺼져도 원본이 깨지지 않는다. 파일 수정 시각은 갱신된다.
- 읽기: JPEG 별점은 파일 헤더(APP1/XMP 세그먼트)만 읽어 파악한다 — 폴더를 열거나 별점을 모아볼 때 파일 전체를 읽지 않는다. PNG는 pyexiv2로 전체를 읽는다.
- 썸네일 캐시: `%LOCALAPPDATA%\WindowPhotoViewer\thumbs\` — 지워도 다시 생성된다.
- 별점 캐시: `%LOCALAPPDATA%\WindowPhotoViewer\ratings.json` — 읽은 별점의 메모(경로·수정시각·크기·별점·라벨). 지워도 다시 채워진다. 종료 시와 모아보기 수집이 끝날 때 저장된다.

## 배포 빌드

```powershell
python -m PyInstaller build/viewer.spec --noconfirm --distpath dist --workpath build/work
dist\WindowPhotoViewer\WindowPhotoViewer.exe
```

폴더 그대로 zip으로 배포하거나(`Compress-Archive dist\WindowPhotoViewer`), 설치 파일을 만들 수 있다:

```powershell
winget install JRSoftware.InnoSetup          # 최초 1회
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" build\installer.iss
dist\WindowPhotoViewer-v0.1.2-setup.exe
```

설치 파일은 기본으로 **현재 사용자 전용**(`%LOCALAPPDATA%\Programs\WindowPhotoViewer`, 관리자 권한 불필요)이며 설치 중 "모든 사용자"를 고를 수 있다. 시작 메뉴 항목·(선택) 바탕화면 아이콘·제거 항목을 만들고, 제거 시 캐시(`%LOCALAPPDATA%\WindowPhotoViewer`)와 설정(`HKCU\Software\WindowPhotoViewer`)도 지운다. 사진 파일에 기록된 별점은 그대로 남는다. 코드 서명이 없어 첫 실행 때 SmartScreen "알 수 없는 게시자" 경고가 뜬다 — "추가 정보 → 실행"으로 넘어가면 된다. 버전을 올릴 때는 `pyproject.toml`과 `build/installer.iss`의 `MyAppVersion`을 함께 바꾼다.
